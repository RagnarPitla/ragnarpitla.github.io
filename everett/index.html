The measured problem

A terminal workspace is not a project reality.

Six unrelated products accumulated in one ad-hoc terminal workspace because the available top-level object grouped terminals, not projects. Names suggested one context while processes were actually running somewhere else.

Window managers can group windows. Terminal runtimes can preserve panes and agent sessions. Everett adds the missing project-level object: a World that supplies the working context and keeps the current project's surfaces legible.

Product model

World, Web, and Board.

01

World

The top-level project reality: workspace folders, terminals, agents, local state, Web links, and visual context.

02

Web

A World-local collection of URLs, tabs, home choices, and launch preferences, separate from the browser target that opens them.

03

Board

A persistent canvas where terminals, notes, drawings, and Web tabs remain arranged as working context across restarts.
